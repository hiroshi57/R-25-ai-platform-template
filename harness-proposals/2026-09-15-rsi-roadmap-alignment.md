## 背景 — なぜこの論文が本ハーネスに直結するか

本 repo の「Self-Tuning Harness Loop」（生ログを要約せず蓄積 → AI にハーネス改善案を出させる →
**人間承認を経て反映**）は、arXiv:2609.11873 の自律性フレームワークで言うと **L2〜L3
（Agent and Harness Search）** に相当し、論文が挙げる **Self-Harness**（実行トレースから
ハーネス編集を提案・テスト）とほぼ同型である。用語の対応:

| 本ハーネス | 論文の概念（§2.2.1 改善ループの解剖 / §1.4 自律性レベル） |
|---|---|
| Worker の実装サイクル | Improver（改善器）が Target を1ラウンド改訂 |
| `worker-report` / `review.json` | Verifier（検証器）による受理/差し戻し判定 |
| `harness-logs/` 生ログ | ラウンド間で継承される Experience / System state |
| 「人間承認を経て反映」「禁止事項・`cc:*` は自動改善対象外」 | §1.3「どの判断が外部（人間）に残るか」／§6「consequential なリリースへの人間権限保持」 |

つまり本論文は、既存ルールの**設計判断の裏付け・引用元**として使える。以下、承認された場合に
反映する 4 提案を diff 形式で示す。**本提案は適用しない**（人間承認後に別コミットで反映）。

## 提案1: retro の切り分け語彙を論文の「RSI 3検証課題」に合わせる（§1.3 / §6 課題1）

**根拠**: arXiv:2609.11873 §1.3。良い候補を生成できても「候補の発見・選択の仕方」を改善したとは
限らない（Autonomy attribution）。永続化しても改善が続くとは限らない（Safe inheritance／
Gödel Agent は 14% の試行で初期性能を下回った）。評価器への反復アクセスは能力向上でなく攻略を
報酬しがち（Reliable verification）。本ハーネスの retro はこれらを区別する語彙を持たない。

**期待効果**: harness-retro の改善提案が「なぜ効いた/効かなかった」を一貫した3観点で切り分け可能に
なり、`escalation_reason` / `reason_code` の再発分析（CLAUDE.md 起動条件）の精度が上がる。

```diff
--- a/.claude/rules/harness-retro.md
+++ b/.claude/rules/harness-retro.md
@@ 提案5「成長前提のストア健全性チェック」の後に新セクションを追加
+
+## 提案6: RSI 3検証課題での切り分け（arXiv:2609.11873 §1.3）
+
+> **承認**: （人間承認待ち）
+
+harness-retro で改善案を評価するとき、次の3観点で「本当に改善したか」を切り分ける。
+単なる自動最適化（1回良くなった）と、改善プロセス自体の改善を区別するため。
+
+1. **安全な継承 (Safe inheritance)**: 変更が後続タスクでも劣化を起こさないか。
+   直近タスクで初期状態を下回った回数を確認する。ロールバック可能性を必須とする。
+2. **自律性の帰属 (Autonomy attribution)**: 良くなったのは「AI が制御した判断」か、
+   それとも固定手続き＋人間の受理基準の効果か。改善の出所を明記する。
+3. **信頼できる検証 (Reliable verification)**: 検証コマンド/評価が「攻略」されていないか
+   （乱数シードのチェリーピック、テスト弱体化、評価器へのラベル抽出）。
+   Worker preflight の「テストを弱める変更の禁止」と対で確認する。
```

## 提案2: `harness-logs/` 逐語保存ルールの根拠に「再現可能な継承インフラ」を追記（§6 課題8）

**根拠**: arXiv:2609.11873 §6「Reproducible Infrastructure for Cross-Round Inheritance」＝
後継システムは「改善がどう得られたか（失敗した代替案・証拠が成り立つ条件を含む）」に
アクセスできる必要がある。再利用可能アーティファクトは *親状態・提案変更・動機づけ証拠・
評価設定・受理判断・その後の利用* を繋ぐべき。これは本 repo の逐語保存ルール（memory-curation.md）と
メタハーネス論文(arXiv:2603.28052)の主張を補強する第2の独立文献となる。

**期待効果**: 逐語保存ルールの根拠が単一文献依存でなくなり、「要約せず生ログ」という運用の
正当性が強化される。ルール改変の圧力に対する防御。

```diff
--- a/.claude/rules/memory-curation.md
+++ b/.claude/rules/memory-curation.md
@@ ルール(MUST) の項目4 の直後に脚注的追記
 4. **`harness-logs/` の生ログは常に逐語保存。** 要約版で置き換えない（グローバル CLAUDE.md セクション7と整合）。
+
+   > **補強根拠 (2026-09-15)**: arXiv:2609.11873 §6「Reproducible Infrastructure for
+   > Cross-Round Inheritance」も、後継が「改善がどう得られたか（失敗した代替案・証拠が
+   > 成り立つ条件を含む）」にアクセスできることを RSI 成立の要件とする。再利用アーティファクトは
+   > 親状態・提案変更・動機づけ証拠・評価設定・受理判断・その後の利用を繋ぐべき、とされる。
+   > 生ログを要約で置換するとこの継承が壊れる。arXiv:2603.28052 と独立に同じ結論。
```

## 提案3: harness-retro の健全性チェックに「継承物の根拠紐づけ（Library Drift 対策）」を追加（§6 課題3）

**根拠**: arXiv:2609.11873 §6「Persistent-State Management and Reliable Reuse」＝
保持しても後続が使うとは限らない（スキルが検索されない／検索しても正しく従わない）。
**Library Drift**: スキルライブラリの肥大が検索を劣化させ改善を停滞させる。継承物には
「根拠・適用条件・依存・観測された効果」を紐づけよ。本 repo の harness-retro.md の
「taxonomy 逸脱」「検索コスト削減」チェックと同じ懸念で、1項目で補える。

**期待効果**: `.claude/agent-memory/` と skills の肥大による検索劣化を早期検知。
既存の taxonomy チェック（提案5）を「中身の有用性」側から補完する。

```diff
--- a/.claude/rules/harness-retro.md
+++ b/.claude/rules/harness-retro.md
@@ 「### チェック項目」の 3 (taxonomy 逸脱) の後に項目4を追加
 3. **taxonomy 逸脱の増加**: フォルダ命名規約から外れたファイル/フォルダが成長とともに増えていないか
    （劣化の早期警告）。逸脱が増え始めたら、人手 or 強いモデルでの再整理をトリガーする。
+4. **継承物の根拠紐づけ (Library Drift 対策 / arXiv:2609.11873 §6)**: 追加された記憶/skill が
+   「根拠・適用条件・観測された効果」を伴っているか。裸の断片が増えると検索が劣化し、
+   検索されても正しく使われない。伴っていない継承物が増え始めたら、統合ではなく
+   root/回帰の再検証をトリガーする（肥大の抑制は逐語保存ルールを侵さない範囲で）。
```

## 提案4: Worker/Lead のエスカレーションを「適応的停止」で言語化（§6 課題7）

**根拠**: arXiv:2609.11873 §6「Adaptive stopping」＝システムは「期待される学習価値と
不確実性」によって実験継続を正当化し、一時停止・人間へのエスカレーション・打ち切りの条件を
明示すべき。本 repo の「自動修正は最大3回、3回目で escalate」（Worker Agent / CLAUDE.md §3）は
その素朴版。閾値の**根拠**を「期待学習価値」で言語化すると説明可能性が上がる。

**注意（保護対象）**: 「3回まで」という**回数そのもの**や CI 失敗時のエスカレーション先
（Cursor）は CLAUDE.md §3 の運用ルールであり自動改善対象外。本提案は**回数を変えず**、
retro 分析時の観点として「同じ失敗の反復に学習価値があったか」を記録する提案に限定する。

**期待効果**: `retries.log` の3試行が「学習価値ゼロの同一失敗の反復」だったのか
「毎回別の仮説を試した」のかを retro が区別でき、閾値調整の材料になる（回数変更自体は人間判断）。

```diff
--- a/.claude/rules/harness-retro.md
+++ b/.claude/rules/harness-retro.md
@@ 提案6（本提案1）の末尾に追記、または独立の運用メモとして
+
+### エスカレーション分析メモ（適応的停止 / arXiv:2609.11873 §6）
+
+retro で `retries.log` を読むとき、3回の自動修正が「同一失敗の無学習な反復」か
+「毎回別仮説を試した探索」かを区別して記録する。前者が多いなら早期エスカレーションの
+価値が高い（が、閾値「3回」の変更・エスカレーション先は CLAUDE.md §3 保護対象のため
+人間判断に委ねる。ここでは観点の記録のみ）。
```
