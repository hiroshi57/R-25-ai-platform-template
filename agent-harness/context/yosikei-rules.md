# ヨシケイ CRレポート — DATA 案件の製品ルール（層2）

分類器が DATA と判定した案件が読む高信号コンテキスト。
出典: グローバル CLAUDE.md「ヨシケイ開発 CRレポート自動化」。

## 絶対制約（層3 ガードレールの根拠）

- 🔒 **クライアントデータ保護**: `data/` 以下は gitignored。コミット・外部送信しない。
- 🔒 **secrets.yaml はコミット不可**（アカウントID記入済み）。
- ⚠️ **FMT(顧客提出用Excel)への書き込みは高リスク**。無人自動実行しない（人間承認が必要）。
- ⚠️ STOP①②③ の Excel `Ctrl+S` は人手の必須手順（`月次運用チェックリスト.md`）。

## 完了条件（層1 契約 done_when の根拠）

- 入力が揃っている（FMT / raw / 簡易参照ツール が存在）。
- orchestrator コマンドが正しく構築されている（必須引数 --fmt/--raw/--tool）。
- 出力FMTがスキーマ準拠・媒体別に突合一致（実行後の検証。ドライランでは対象外）。

## ドライラン方針

- orchestrator.py は **--dry-run を持たない**ため、ハーネス側のドライランは
  「コマンド構築＋入力パス検証（読取のみ）＋ログ出力」に限定し、**実行しない**。
- Vercel は読取専用（`vercel projects ls` 等）。deploy は本番禁止のため絶対に自動化しない。
